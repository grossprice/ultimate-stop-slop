# Interface copy

A screen shows only what the reader needs. Everything else is a distraction.

## Labels are noun phrases

Read a label on its own, out of context. If it is a clause instead of a noun phrase, it is
caption text sitting where a label belongs.

**"Every X" where "all" is the word.** A quantifier read once is fine. Read forty-seven times
across a product it is a tic, and a reader notices before you do.

| Avoid | Use instead |
|-------|-------------|
| Every answer / See every answer | All answers |
| Every source | All sources |
| Every item | All items |
| Every state | All states |
| Every run for this site | All runs for this site |

"Every day", "every three days" and "every plan" stay. Those are a cadence and a scope, and
"all days" is not English.

**A toggle written as an instruction.** "Read it as a table" tells the reader what to do with
the thing instead of naming it. Name the view: "Table view", "Chart view".

**A label written as a sentence about the reader.** "How often customers opened your emails."
is a caption pretending to be a label. Name the metric: "Open rate".

**A question-fragment heading.** "Did anything move" becomes "Trend". If a chart already
answers the question, the heading does not need to ask it.

**A label that narrates.** "What your customers bought" becomes the thing under it: "Top products".

## No helper text by default

- Labels and titles stay. The sentence explaining a field, card or option does not render.
- An explanation worth keeping sits behind an info hint: a small (i) icon that shows the text
  on hover or focus.
- The only always-visible text under a heading is live data: a date, a count, a status. Never a
  description of the thing above it.
- When unsure whether a field needs its explanation, ask about that field. Don't default either
  way.

## No example lists

- No "e.g. X, Y, Z" and never exactly three items offered as illustrative examples.
- A placeholder is one plain word. A search input says "Search".
- Two inputs in one viewport never share a placeholder. "Filter orders" and "Search" beat two
  inputs that both say "Search".

## Buttons and options are names

- A button or list option is a name, not a name plus a blurb. Two lines of prose under a bold
  option title belong behind an info hint.
- No reassurance tagline under a call to action ("No credit card needed. Cancel anytime.
  Setup in minutes."). Cut it, or keep the one fact that matters: "Card required. Cancel
  anytime."

## Numbers

- Percentages use %. Never "pts".
- A figure carries its sample where it appears. See claims.md.

## Length

A UI string over 30 words is too long. Say it shorter, or move the detail behind an info hint.

## Errors and empty states

- An error names its cause and the next step: "Could not reach example.com: DNS lookup failed.
  Check the domain and try again."
- An empty state says what is missing and what fills it: "No checks yet. The first one runs
  tonight."
- Neither blames the reader.

## One name per thing

The same metric, page or object has one name across every screen. See claims.md.
